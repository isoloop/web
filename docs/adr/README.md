# Architecture decision records

Decisions about this repo: the site, the examples and the design system. Decisions about Isoloop itself are in the library repo's [ADRs](https://github.com/isoloop/isoloop/tree/main/docs/adr).

Each has a status:

- **Proposed:** a recommended default, open to review.
- **Accepted:** binding; change it only with a new ADR that supersedes it.
- **Rejected / Superseded:** kept for history.

| ADR | Decision | Status |
| --- | --- | --- |
| [0001](0001-what-this-repo-is.md) | `isoloop/examples` renamed to `isoloop/web`: the site, examples and design system, built on the published packages; the library repo keeps the library and its docs; served at `isoloop.dev` with sections as paths; one Pages build per tag (`markets-v*`, `plant-v*`, `basic-v*`, `site-v*`); ADR 0009's toolchain by reference; amended 2026-11-28 by 0007: a preview is a second site at `next.isoloop.dev`, not a section (Proposed) | Accepted |
| [0002](0002-site-build.md) | `apps/site`: Vite multi-page, plain HTML and CSS, no UI, CSS or template framework; meta CSP `default-src 'self'`, every request same-origin, JS only as enhancement; only basic runs live (iframe), plant and markets as cards; hub from each app's `example.json`; diagrams fetched from `isoloop/isoloop` at a pinned sha; figures copied with their tag; M4 docs behind an interface we own; the theme in `localStorage`, switched live across same-origin frames; decision 1 amended by 0003; amended 2026-11-14 for the approved design (`/features/`, the new landing order, demos drawn from basic's real activity over origin-checked `postMessage`, markets figures until M3f); amended 2026-11-21: one panel per example page, basic and both processor pages live on the hub (`?embed=1&start=manual`, the idle app under the site's Start, no worker before it, reset on leaving), the full pages kept, intros written once in `example.json`, the Devtools switch on every page that runs Isoloop | Accepted |
| [0003](0003-design-system.md) | `packages/ui` (private, unversioned): Preact components rendered at build time only, behind our own `render()`, no framework JS in the browser; tokens in CSS with the `--ui-` prefix (primitives and semantic layers), colours in `oklch()`, light and dark through `data-theme`; `ui-` classes in `@layer ui`; the full header on the site and basic, a fixed-dark bar on the dashboards; AA contrast by test; the logo in `brand/`; amends 0002 decision 1; amended 2026-11-14 for the approved design (Archivo self-hosted, concept A's palette with `--ui-part-*` colours, a gutter layout, motion only in the live demos, a sticky header, the sun/moon switch); amended 2026-11-21: the page at 96rem, one grid for every page (`--ui-gutter` 16rem and its gap hold the rails, the docs' sidebar, the mark and the section headings), two widths (a text measure, figures at the full column), the dark background `#171b26`, calm reading (`--ui-prose`, more leading, 18px body), pills centred optically, one Devtools switch | Accepted |
| [0004](0004-publishing-and-governance.md) | Publishing and governance: Changesets in both repos (library in pre mode `next`, `0.1.0-next.N`; apps versioned with their tags, a GitHub Release per tag), `/changelog/` on the site; a definition of done with a Site impact line; gates from `AGENTS.md` through Claude Code hooks and CI (changeset, Site impact, the library's API check) to a site steward reviewing every PR in both repos (blocking on must-fix, maintainer override) and auditing weekly; the publish skill; feature entries as data with proof links; a Publishing queue; amended 2026-11-20: `maintainer-approved` clears only the steward's "Needs the maintainer" item, `steward-override` still skips the review | Accepted |
| [0005](0005-page-navigation-and-status-marks.md) | Page navigation and status marks: the step tabs on every long page, one script, a hash inside a panel opens it, the tab row scrolls sideways only; `/features/` in six tabs (`tab` in each entry) and opened by sticky notes, one column per tab, one note per feature (checked by a test; the blueprint first chosen is an alternative) in place of the lede and the 12-feature list; `experimental: true` drawn as an outlined orange pill (`.ui-pill`, `--ui-experimental`, AA by test) wherever a feature's name shows; amends 0002 and 0003; amended 2026-11-20: in navigation lists the mark is a compact round "!" with a hidden label and a tooltip, the pill stays on headings and the docs index; amended 2026-11-21: the step tabs give way to the docs' left rail on Features, How it works and Examples (plain group headings, one accent bar, the shared scroll-spy, folded on phones), the sticky notes stay as Features' opening, one Previous/Next pager with chevrons, one panel heading style | Proposed |
| [0006](0006-docs.md) | Docs: the guides stay in `isoloop/isoloop` and the site renders them at `/docs/` from a published-version pin, with "Docs" in the nav; `markdown-it` behind our own `renderMarkdown`, our own tokenizer, no front matter, links rewritten; `llms.txt`, `llms-full.txt` and a `.md` per page; the implementing agent writes docs with the library's `docs` skill and `docs/writing.md`, one guide skeleton, a docs map, `docs:check` in the hook and CI, the steward reviewing and a weekly drift pass; the API and CLI reference generated from the published `.d.ts` and complete TSDoc; our own search; amends 0002 and 0005, extends 0004; amended 2026-11-20: the API read through `readApi` on tsrs, and coverage with a shrinking `pending` list; amended 2026-11-20: public pages say how it works, not why (no ADR or plan references), and the API reference comes before the docs go live; amended 2026-11-21: the search (`/docs/search.json` from the rendered pages, our own matcher behind an interface with a conformance suite, loaded on first use, a combobox at the top of the sidebar, hidden without JS), the `llms.txt` line on `/docs/` and "View as Markdown" on every page | Accepted |
| [0007](0007-site-preview.md) | The site preview: the apps on `main` stay on the release the live docs describe; previews are seen at `next.isoloop.dev`, the whole site built from a long-lived `next` branch on the latest library preview, served by the small repo `isoloop/next` that calls this repo's `deploy.yml` (inputs `ref`, `preview`), deployed by hand with no tag; a banner on every preview page and a "Preview" link in the stable header; the preview out of search; every minor's release also publishes the next minor's `-next.0`, so a preview always exists; amends 0001 | Proposed |
