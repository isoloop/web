# The site after 0.1.0: benchmarks, alternatives and the audit's fixes

**Goal:** the site shows Isoloop's costs and gains as charts on a page of their own, compares Isoloop with the alternatives, and fixes what the external 0.1.0 audit (2026-11-24) found on the site. A stable benchmark build, `plant-bench`, measures every minor and major release from now on.

**Done when:** the tasks below are closed, `/benchmarks/` and the features page's Compared tab are live with plant-bench's 0.1.0 results, and the site is pinned to the library's 0.1.1.

**Progress:** [web#302](https://github.com/isoloop/web/issues/302) tracks it, with one sub-issue per task. A PR closes its task with `Fixes #N`. This file holds no checkboxes.

**The library side** is `isoloop/isoloop` `docs/plans/0.1.1-patch.md` (tracking isoloop#415). The guides, API pages, `llms*.txt` and diagrams come from there through `apps/site/library.lock`, so their fixes reach the site only at the pin bump (S12). Don't fix them here.

## Decisions (2026-11-24, grilled Q1–Q26, maintainer, yes to all)

### plant-bench

1. **Plant, not markets.** Plant has the full matrix (native, native + workers, Isoloop `one`, `matched`, `split`), and every published figure comes from it. Markets stays for feature benchmarks.
2. **A copy at `apps/bench/plant/`**, taken from plant at a tag matching `@isoloop/*@0.1.0`. Every dependency is pinned exactly, with no `catalog:`, the browsers included through the Playwright image. The live plant example stays free to change.
3. **Its code changes only at a generation:** 0.1 now, then 1.0 and 2.0. Between those, `main` never changes it.
4. **A run:**
   - Open a branch and bump `@isoloop/*` to the release.
   - If the release breaks an API the bench uses, run `isoloop migrate` (the library's codemod rule), never a hand fix. A codemod that fails on plant-bench blocks that release.
   - Run, then open a PR to `main` with only `apps/bench/plant/results/<version>/`: the raw JSON, `summary.md`, the exact versions, the browser builds, the machine, and any "adapted for" note.
   - Delete the branch.
5. **It runs at every minor and major release** (0.1.0 as the baseline, then 0.2.0, 0.3.0 … 1.0.0), never at a patch. Always on bench machine 1, on the maintainer's go.
6. **The matrix is fixed:**
   - builds: native, native + workers, Isoloop `one`, `matched`, `split`;
   - load: 1 and 5 kHz;
   - figures: main-thread busy, all-thread CPU, typing median, first data, all widgets with data, recovery after a 3 s block, memory after GC;
   - engines: Chromium for everything, Firefox and WebKit for the timings every engine can read;
   - 5 interleaved rounds on the server's 4 cores at 2.0 GHz.
7. **Regressions:** the benchmarks page shows each figure across versions and flags a change beyond the run's own spread. There's no CI gate, since the server run is manual. CI only smoke-tests plant-bench: it builds, and one short round runs.
8. **A new feature gets its own `apps/bench/<feature>/`,** under the same rules from its first run. plant-bench is never extended.

### Pages

9. **`/benchmarks/` is a top-level page in the main nav:**
   - the latest results as charts, with the full tables folded under them;
   - the history across versions, shown once there are two;
   - the method (machine, rounds, the paired Δ);
   - the feature benchmarks;
   - links to the raw results.
10. **The home page's costs table becomes four small charts,** `matched` against native + workers: main-thread busy and typing median (gains), all-thread CPU and memory after GC (costs), then a link to `/benchmarks/`. "What it gives" stays, its Isoloop column labelled `matched`.
11. **Alternatives:**
    - **Home:** a short table after "What Isoloop can't hide", with Isoloop and the six alternatives as rows and 3–4 columns of marks, then a link.
    - **Details:** a new **Compared** tab on `/features/`.
    - **Rows:** Remote DOM, Partytown, worker-dom, Comlink + workers, cross-origin iframes, `scheduler.yield()`.
    - **Columns:** UI in a worker, supervision and restart, a durable bus with replay, a security boundary, browser support, the main cost.
    - **Marks:** yes, no or partial, each sourced from that project's own docs with a link and the date checked.
    - **Wording:** neutral, and it says where an alternative is the better choice (iframes for hostile code).
    - **Benchmarks:** none against the alternatives.
12. **Charts are our own static SVG:** a component in `packages/ui`, rendered at build time from the results JSON, with no chart library and no JS in the browser (`default-src 'self'` holds). Light and dark, following the `dataviz` skill. Paired bars: grey for the baseline, one colour for better and one for worse, the sign also in words.
13. **Data at launch:** the pages ship today on the current plant figures, each labelled with what it was measured on (plant at `@isoloop/*@0.0.0-next.b8ffdcf`, 2026-11-13, the 4-core machine). Tonight, once the server is free of jsbench, the maintainer runs plant-bench on **0.1.0** and the figures are swapped (S13). The audit's "re-run on 0.1.0" is that run.

### The audit's site fixes

14. **Search titles:** check them against `.claude/plans/2026-11-22-seo-decisions.md`. Add "TypeScript" or "Web Workers" only where a title doesn't already say what Isoloop is.
15. **The processor example passes `loads`,** so no consumer is shown as quarantined at start. The library keeps its API in 0.1.1 (isoloop#346).
